# Contributing (DRAFT — not yet open for general code submissions)

1. Work only on issues explicitly labeled as approved community scope (documentation, UI accessibility, or synthetic QA).
2. Work from a fork and make a small pull request; never request production push, administrator, customer-data or credential access.
3. Use synthetic data only. Never submit real phone numbers, customer messages, store events, token values or unauthorized merchant media.
4. Include scope, tests, security implications, compatibility notes, rollback and reviewer evidence.
5. Human review by the project owner is required; no unattended merge or production deployment.
6. Disclose substantial AI-generated changes and verify provenance, compatibility, security and tests.

**License and IP:** All contributors must have rights to the contributed material. Licensing and contributor terms are not yet approved. No contribution conveys a right to access private business code.

Report vulnerabilities privately per SECURITY.md, not in public issues.
